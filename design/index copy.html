Motion that explains change

Motion is not decoration applied to a transition. It is an explanation of what just changed — where it came from, what it became, and whether you can interrupt it. If it does not explain something, it is costing frames to say nothing.

  • 14 sections
  • 4 live demos
  • 18-point audit
  • Reduced-motion safe

Reduced motion is on. These demos replace movement with an instant state change — which is the rule, applied to itself.

01

The gate

Before choosing a curve or a duration, answer a harder question: should this animate at all? The most expensive mistake in interface motion is animating something the user sees a hundred times a day.

How often the user triggers itDecision
100+ times a day — keyboard shortcut, command palette, tab switchNo animation. Ever. Latency is the feature. Stop here.
Tens of times a day — hover, row navigation, togglesNear-imperceptible only: ≤150ms, opacity or colour, or nothing.
Occasional — modal, drawer, toast, menuStandard animation. This is the bulk of your motion system.
Rare or first-time — onboarding, success, empty stateThe delight budget lives here, and only here.
 Keyboard-initiated actions are a disqualifier, not a judgment call. Something opened fifty times an hour should appear, not arrive.
  1. Frequency outranks beauty. A beautiful 400ms open on a command palette is a 400ms tax on every use.
  2. Never animate to hide latency. Fix the latency; a spinner with personality is still a spinner.
  3. One idea per moment. Moving, fading, blurring and scaling at once reads as a special effect, not a explanation.
  4. No animation is a valid answer. State it in the review so the next person does not "fix" it.
02

Purpose

Name the purpose in one word before writing a line of code. If you cannot, you are about to add noise.

Feedback

Confirm the interface heard the user. Press, toggle, submit. Fast and small.

Spatial consistency

Show where something came from or went. Popover from its trigger; sheet from the edge.

State indication

Make a change legible: saved, selected, syncing, failed.

Prevent a jarring change

Bridge content that would otherwise teleport — reorder, expand, replace.

Explanation

Demonstrate how something works. Marketing, onboarding, empty states.

Delight

Allowed once, at the rare tier. Never on a repeated action.

The function test

Data someone is reading or acting on should not move for style. A mouse-tracking parallax belongs on a marketing page, never on a chart in a banking app. If the motion makes a value harder to read for a moment, it is a bug with a nice curve.

03

Duration

Duration is a function of distance, mass and frequency — not of how impressive the transition should look. A 400ms modal feels considered once and sluggish by the tenth open.

ElementDurationNote
Hover / press100–150msFast enough to feel like a physical response.
Tooltip125–150msAdd a 300–500ms open delay so it does not flash while crossing.
Dropdown / menu150–200msOrigin at the trigger.
Popover180–220msScale .96 → 1 plus opacity.
Modal200–250ms300ms on mobile where the travel distance is larger.
Drawer / sheet250–350msLonger because the distance is real, and users track it.
Accordion / expand200–300msThe one place height animation is tolerated.
Toast150ms in / 100ms outExits are always shorter.
Page / view transition250–400msAbove 400ms the app feels like it is thinking.
Success celebration600–900msOnce per journey. Never looping.
 Scaling with distance: 0–100px → 150ms, 100–400px → 200–250ms, full-screen → 300–400ms. Do not scale linearly; perception is logarithmic.

Identical distance, identical curve. The 400ms version feels like it is waiting for permission. Most interface motion people describe as "smooth" is simply shorter than they expected.

Perceived duration

ease-out at 200ms feels faster than ease-in at 200ms, because most of the visible travel happens early. Users judge motion by when it stops changing, not by the clock. This is why fixing the curve often fixes "it feels slow" without touching duration.

04

Easing

Easing states where the energy goes. Objects entering the screen decelerate; objects moving across it accelerate then settle; things that never stop move at a constant rate.

SituationCurveWhy
Entering or exitingcubic-bezier(.2, 0, 0, 1)Fast start, long settle. The default for almost everything.
Moving on screencubic-bezier(.65, 0, .35, 1)Ease-in-out. Something already visible changes position.
Hover / coloureaseSmall state change; curve barely matters, duration does.
Constant motionlinearProgress bars, marquees, spinners. Anything that loops.
Expressive settlecubic-bezier(.16, 1, .3, 1)Very fast start, strong deceleration. Use sparingly.
 Never ease-in on UI. It starts slow — delaying the exact frame the user is watching — then arrives abruptly.

05

Springs

A cubic-bezier is a fixed timeline. A spring is a physical system that answers to the user's hand mid-flight. That difference decides which one you need.

Use a spring when

  • The motion is gesture-driven — drag, swipe, sheet, pull-to-refresh.
  • The user can interrupt or reverse mid-animation; a spring carries velocity, a curve restarts.
  • Elements have mass that should feel consistent at different distances.
  • You need layout animation where the start and end are measured at runtime.

Parameters that actually matter

SettingUI defaultEffect
Bounce0Any bounce above ~0.2 reads as playful, not physical. Make it deliberate.
Duration (perceived)0.3–0.5sSpring "duration" is when it settles, not when it stops technically.
Stiffness300–400Higher = snappier. Above 500 starts to feel nervous.
Damping28–40Lower = more oscillation. 1:10 damping:stiffness is a stable default.
Mass1Change this only to make big objects feel heavier, not to tune speed.
 In Motion: { type: "spring", duration: 0.35, bounce: 0 }. In CSS, approximate with linear(), or use a curve and accept no interruption.
The bounce trap

Bounce is the most over-used parameter in interface motion because it is the most visible in a demo. A button that springs past its target implies it overshot something — which is wrong for a save action and right for a toy. Default to zero; earn each 0.1.

06

Choreography

When several things move, the order is the message. Simultaneous motion says "these are one object"; staggered motion says "read this first, then this".

  • Open source fellowship21 Nov
  • Research internship, Lisbon30 Nov
  • Product design scholarship05 Dec
  • Graduate scheme, remote12 Dec

0ms is correct for a list that appears on every visit. 40ms reads as hierarchy. 100ms on five rows means the last row arrives 500ms late — fine once, hostile on a filter change.

The rules

  • Stagger 20–40ms for list items and grid children; 60–100ms only for staged, infrequent entrances. Keep total choreography under ~400ms.
  • Cap the count. Stagger the first 6–8 items, then enter the rest together. Otherwise row 40 arrives next Tuesday.
  • Overlap, don't queue. Each item should start before the previous finishes — roughly 30–50% overlap. Sequential motion feels like a slideshow.
  • Origin at the trigger for popovers, menus, tooltips. Modals are exempt: they are not anchored, so they stay centred.
  • Follow-through only in expressive motion. A settle that overshoots on a menu is a delay with extra steps.
07

Enter & exit

Entrances can afford to be generous. Exits cannot: by the time the user dismisses something, they have already moved on. Exit shorter, exit smaller, and never animate from nothing.

Demo 04 · Asymmetric enter / exit
Saved to your list

You can undo this for 5 seconds from the toast.

Enter 300ms · +12px · opacity 0→1 Exit 150ms · −8px · opacity 1→0

The exit travels less than half the distance in half the time. Same component, two intentions: arrive clearly, leave immediately.

Enter

  • Start from scale(.96–.97) and opacity: 0. Never scale(0) — nothing in the physical world appears from nothing, and the eye catches the pop.
  • Translate 4–16px in the direction of origin. More than that and it looks like it fell in.
  • Optional 4px blur on expressive entrances only. Blur is a paint cost; do not put it on a repeated action.

Exit

  • Roughly half the duration and half the distance of the entrance.
  • Fixed exit offset (−8px), never the full container height — collapsing height is the slowest thing you can animate.
  • Remove instantly where motion adds no information. A tooltip does not need a farewell.
  • If the destination matters (drawer closing back to its trigger, item flying to a cart), then travel fully and let the exit be the explanation.
08

Interruption

Users do not wait for your animation to finish. The quality of an interface is largely the quality of its response to being interrupted.

MechanismBehaviour on interruption
CSS transitionRetargets from the current computed value. Good default for state changes.
CSS keyframesRuns a fixed timeline. Restarts or jumps — cannot reverse. Reserve for one-shot sequences.
Spring (Motion / Reanimated)Carries velocity into the new target. The only mechanism that feels physical mid-gesture.
WAAPIRetargets if you cancel and re-run, but velocity is lost unless you cancel with a computed offset.
 Rule: interactive state uses transitions or springs. Keyframes are for things that play once and end.
  • Never queue. If the user clicks again, the new intent replaces the old one. A queue is how a fast clicker ends up watching a 3-second animation after they stopped caring.
  • Never block input during motion. The animation is feedback, not a gate.
  • Cancel on unmount. Animating a detached node is a memory leak with a nice curve.
  • Prefer opacity for reverses. Reversing a translation mid-flight can produce a visible snap where the two curves meet.
09

Feedback latency

Perception has three thresholds. Every loading pattern is a decision about which one you are inside — and the wrong pattern is worse than none.

TimeUser's stateWhat to show
0–100msFeels instantNothing. Adding an indicator here makes it feel slower.
100ms–1sFlow preservedImmediate press state, then a subtle indicator after ~300–500ms. No spinner flash.
1–10sAttention heldDeterminate progress if you can estimate it; skeleton matching the final layout.
10s+Attention lostReal progress, a cancel path, and the ability to leave and come back.
 Delay every spinner by 300ms. A flash of spinner on a 120ms request reads as instability.

Optimistic, pessimistic, and when each is honest

  • Optimistic — apply the change now, reconcile later. Use when failure is rare and rollback is cheap and visible (likes, reorder, mark-as-read). Never for payments, deletions, or anything a user would screenshot as proof.
  • Pessimistic — show progress, then commit. Use when the server can reject for reasons the user must act on.
  • Hybrid — optimistic with a quiet "saving…" and a real error state. This is what mature products converge on.

Whatever you pick, the static cue must survive: a label, an icon, a colour. Motion is never the only channel that reports state.

10

Performance

A dropped frame is not a technical detail. It is the exact moment the interface stops feeling like an object and starts feeling like a website.

composite 2mspaint + raster 10mslayout 4ms
16.7ms budget @ 60Hz8.3ms @ 120HzJank starts when this bar overflows

Cheap, expensive, forbidden

PropertyCostNote
transform, opacityComposite onlyRuns on the compositor. The only two you should reach for by default.
clip-path, filterPaintSanctioned for reveals; blur is much heavier than a clip.
box-shadow, backgroundPaintFine on small elements, costly on large surfaces or during scroll.
width, height, top, left, marginLayoutTriggers layout for the element and often its siblings. Never for motion.
height for accordionsLayout (tolerated)The one exception, because there is no transform equivalent.

Rules that survive profiling

  • CSS beats JS under load. CSS animations run off the main thread; requestAnimationFrame drops frames while the browser parses, loads and paints. Use CSS for predetermined motion, JS for dynamic and interruptible motion.
  • will-change is a painkiller, not a vitamin. Add it only after observing first-frame stutter, name the actual property, and remove it after the animation.
  • Never transition: all. Name the properties; otherwise you animate layout by accident.
  • Contain isolated movers with contain: layout paint so a moving card cannot invalidate the page.
  • Full transform strings in Motion. x/y shorthands are not hardware-accelerated; transform: "translateX(100px)" is.
  • Never drive a child's transform from a parent CSS variable — it recalculates styles for every child.
11

Accessibility

Motion is an accessibility surface, not a finishing touch. For a meaningful share of users, the wrong movement is nausea, not polish.

Reduced motion is a fallback, not a deletion

/* movement off, meaning kept */
@media (prefers-reduced-motion: reduce) {
  .toast {
    transition: opacity 120ms linear;
    transform: none;
  }
}

Replace translation and scale with an opacity cross-fade. Do not remove the transition entirely and do not make content conditional on animation completing — under reduced motion, the state must still arrive.

Triggers to avoid regardless of preference

  • Large-area parallax and background movement behind reading content.
  • Zoom or scale beyond ~1.1× on a large surface; it simulates forward motion.
  • Spinning objects larger than an icon.
  • Flashing above 3Hz, ever.
  • Autoplaying motion longer than 5 seconds without a pause control.
Non-negotiable

Every animated state change also leaves a static cue — colour, icon, label, position. If the only evidence that something happened is that it moved, a user with reduced motion or a screen reader was told nothing.

Anti-slop

Twelve motion tells that read as generated, assembled, or borrowed from a Dribbble shot that was never used.

TellWhat it signals, and the fix
Bounce on every elementPlayfulness applied indiscriminately. Set bounce: 0; earn each increase.
500ms hover statesSlow reads as laggy, not luxurious. 100–150ms.
scale(0) entrancesObjects appearing from nothing. Start at .96 and fade.
ease-in on UIDelays the exact moment the user is watching. Use ease-out.
Every section animates on scrollContent that is not there when you arrive. Animate once, or not at all.
Infinite float / pulse / shimmerPermanent motion with no state change. It also never stops costing frames.
Keyframes on a toggleCannot reverse; snaps on a double click. Use a transition.
100ms stagger on nav itemsNavigation is high-frequency. Stagger belongs to infrequent entrances.
Animating height, width, topLayout thrash. Transform instead.
Blur transitions everywhereExpensive, and it smears text. One blur per page is plenty.
Parallax on body copyReading while the page moves. Vestibular hostility.
Motion as the only feedbackNothing is announced to assistive tech. Add a static cue.

What this skill refuses to call motion design

  • Animation whose purpose is "it looks cool" on a repeated action
  • Longer duration used to imply quality
  • Bounce used to imply personality
  • Scroll-jacking described as storytelling
  • Loading animation standing in for a performance fix
  • Motion shipped without a reduced-motion path

14

Tokens

A motion system is four scales: duration, easing, distance, and stagger. Everything else is a component decision that should reference one of these.

/* duration */
--dur-instant: 100ms;   /* press, toggle */
--dur-fast:    150ms;   /* hover, exit, tooltip */
--dur-base:    200ms;   /* menu, popover */
--dur-slow:    300ms;   /* modal, drawer, page */
--dur-express: 900ms;   /* once-per-journey delight */

/* easing */
--ease-out:  cubic-bezier(0.2, 0, 0, 1);
--ease-move: cubic-bezier(0.65, 0, 0.35, 1);
--ease-snap: cubic-bezier(0.16, 1, 0.3, 1);
--ease-linear: linear;

/* distance — keep entrances small */
--d-nudge: 4px;  --d-in: 12px;  --d-out: -8px;

/* choreography */
--stagger-list: 30ms;
--stagger-hero: 80ms;

/* the default transition */
--t-state: background-color var(--dur-fast) ease, border-color var(--dur-fast) ease;
